# Decision Log

デザインの判断と理由を、あとから引き継げる形で残す小さなツールです。ポートフォリオの補足スライドを作るときの「選定理由の言語化」にも使えます。

- 動かす: `decision-log/index.html` をブラウザで開く（外部サービスへの依存なし）
- データ: 入力内容はブラウザの localStorage に保存されます。「初期状態に戻す」で初期化できます
- 「サンプル: 家計簿アプリ」はすべてダミーです。COFFEE TETHER と Synapse の項目は、コードから読み取れる事実（書体・色など）だけを入れ、**理由は未記入**にしてあります

## 課題の整理（下書き）
`【要記入】` は本人の経験・事実でしか書けない部分です。書けないものは書かずに残します。

| 項目 | 内容 |
|---|---|
| 誰が困るか | デザインの判断を引き継ぐ人（デザイナー、エンジニア、後から入るメンバー）。仮説 |
| 何に困るか | 値は残るが理由が残らない。変更してよいかどうかを判断できない。仮説 |
| 課題の見つけ方 | 【要記入】（例: 就活で選定理由を問われたとき、自作の2作品でも理由を即答できなかった、など実際の経験） |
| 既存の代替手段 | 【要記入】（例: 設計ドキュメント、チャット履歴、コメント、Figmaの注釈など、実際に見たもの） |
| 検証したか | 【要記入】（誰に見せて何を直したか。していなければ「未検証」と書く） |

## 設計上の判断（理由つき）
| 判断 | 理由 | 却下した案 |
|---|---|---|
| 「理由」「却下案」「根拠」「決めた内容」の4点で充実度を数える | 理由だけでなく、選ばなかった案まで書かせると、判断の筋道が後から追える | 自由記述1欄のみ（書き方が人によって変わり、抜けに気づけない） |
| 根拠の強さを4段階で示し、記号と文言を併記する | 感覚だけの判断と、観察に基づく判断を区別するため。色だけで伝えない | 色分けのみ（色覚の違いで伝わらない） |
| デザイナー表示とエンジニア表示を切り替える | 同じ記録でも、見る人が必要とする情報は違うため。エンジニア側は「値」と「変更前に知ること」に絞る | 1つの表示で全員に見せる（情報が多く、実装時に探しにくい） |
| 画面の一覧を左、判断を右に置き、上に全体の状況を出す | 「理由が未記入」の件数を最初に見せ、詳細へ降りていく流れにするため | 判断の一覧だけを出す |
| 外部CDNを使わず単一HTMLにする | 回線が不安定でも動かすため | ライブラリで見た目を整える |

## 既知の限界
- 保存先はブラウザ内のみで、複数人での共有や同期はできません
- 画像の添付、バージョン履歴、承認フローは未実装です
- ユーザーによる検証は行っていません【要記入: 行ったら結果を追記】
